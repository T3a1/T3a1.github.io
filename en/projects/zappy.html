NAME

zappy — multiplayer simulation where teams of AIs compete

SYNOPSIS

zappy_server -p port -x width -y height -n team… -c players -f freq

zappy_ai -p port -n team [-h machine]

zappy_gui -p port -h machine

DESCRIPTION

The end-of-year project of the second year, built by five. On a map shaped like a torus, teams of AIs gather food and stones and level up through group rituals. The first team to bring six players to the top level wins. Three separate programs only talk over TCP.

zappy_ai ──┐
zappy_ai ──┼── TCP, text protocol ──► zappy_server ◄── TCP ── zappy_gui
zappy_ai ──┘                           (C, poll)            (C++, raylib)

ROLE

I led the team (architecture, task split, integration of the three parts) and wrote the server with a teammate.

DESIGN

  • No threads on the server. A single poll() loop serves every client, so the game state never needs a lock.
  • Game time. Each player has a command queue, and each command lasts a number of time units set by the frequency -f.
  • Two protocols. One for players (move, look, take, broadcast a message), one for the viewer, which receives every event live.
  • AI. A state machine (survive, gather, rally, level up); a leader is elected and calls its team through broadcasts.
  • Tests. Server unit tests with Criterion: argument parsing, map, network, world.
