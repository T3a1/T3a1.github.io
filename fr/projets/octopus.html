NOM

octopus — déployer une application à cinq services sur des machines virtuelles

SYNOPSIS

ansible-playbook -i production playbook.yml --ask-vault-pass

DESCRIPTION

Une seule commande installe et démarre toute l'application de vote sur cinq machines virtuelles ; la relancer ne change rien. Projet de 2e année. La même application est déployée sur Kubernetes dans bernstein(8).

votants ──► poll ──► redis ──► worker ──► postgresql ◄── result ◄── lecteurs
           (VM 1)   (VM 2)    (VM 3)       (VM 4)        (VM 5)

CONCEPTION

  • Un rôle par service. base, redis, postgresql, poll, worker, result. Chaque rôle installe son environnement (virtualenv Python, Maven, Node.js) et un service systemd.
  • Idempotence. Chaque tâche décrit un état voulu ; les handlers ne redémarrent un service que si sa configuration a changé.
  • Secrets. Le mot de passe de la base est chiffré avec Ansible Vault ; la clé SSH, le fichier de mot de passe du coffre et l'inventaire réel restent hors du dépôt.
  • PostgreSQL 16 depuis le dépôt officiel, schéma appliqué et accès restreint dans pg_hba.conf.
