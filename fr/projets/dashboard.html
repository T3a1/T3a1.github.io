NOM

dashboard — tableau de bord personnel de widgets web

SYNOPSIS

docker compose up [--build]

DESCRIPTION

Chaque utilisateur choisit des services (météo, cryptomonnaie, NASA, Duolingo, GitHub) et place leurs widgets sur une grille. Chaque widget a ses réglages et sa fréquence de rafraîchissement, de 10 secondes à une journée. Projet de 3e année, en binôme.

navigateur ──► nginx ──┬── application React (fichiers statiques)
                       └── /api ──► API .NET 10 ──┬── PostgreSQL
                                        │         └── Mailpit (e-mails)
                                        └── rafraîchissement en arrière-plan
                                            ──► Open-Meteo, CoinGecko, NASA,
                                                Duolingo, GitHub

RÔLE

J'ai écrit l'API .NET et sa suite de tests, la connexion avec Google et Microsoft (OpenID Connect), la liaison de compte GitHub par OAuth, la mise en conteneurs et la documentation. Mon binôme a réalisé l'interface React.

CONCEPTION

  • Rafraîchissement côté serveur. Le serveur met à jour chaque widget en arrière-plan et garde le dernier résultat ; la page ne fait que le lire. Cent onglets ouverts ne font pas cent appels au fournisseur météo.
  • Pas de mot de passe tiers. GitHub se lie en un clic sur sa propre page d'autorisation ; aucun mot de passe ni clé n'est saisi dans l'application.
  • Comptes. Inscription confirmée par e-mail, connexion par jeton, rôle administrateur pour gérer les comptes.
  • Tests. 193 tests d'intégration xUnit, avec des faux fournisseurs (météo, GitHub, OIDC…) pour ne dépendre d'aucun service extérieur.
  • Lancement. Une seule commande docker compose up : base de données, boîte mail de test, API et interface.
  • Décisions documentées. Seize décisions de conception, chacune avec les options envisagées, ce qu'elle apporte et ce qu'elle coûte.
