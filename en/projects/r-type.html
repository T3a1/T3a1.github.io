NAME

r-type — networked multiplayer shooter for up to 4 players

SYNOPSIS

./rtype.py [--native] [-c clients]

./rtype.py --server-only [--native]

./rtype.py --clients-only -H host

DESCRIPTION

A networked remake of the 1987 arcade game, built in third year by a team of four. Up to four players team up against waves of enemies and bosses. The server is the only judge of the game: clients send it their inputs and draw the state it sends back. The game runs on Linux and Windows.

ROLE

I laid the foundations of the client, the server and the first ECS, then designed the protocol and the network layer. I wrote the client-side interpolation and prediction, the rooms and lobby, the server's admin console, the chat, the end of game, the CI and the rtype.py launcher. I authored about 140 of the 340 commits.

DESIGN

  • Binary protocol over UDP. 12-byte header, 16-byte entity records, datagrams of at most 1200 bytes so IP never fragments them. Every field is read and checked one by one: a malformed packet is dropped whole.
  • Reliability where it matters. Events (joining, chat, game over) are numbered and acknowledged. Snapshots and inputs are not: a late state is useless anyway.
  • Authoritative server. 60 ticks and 20 snapshots per second. Networking runs on its own thread and talks to the game loop only through queues.
  • Latency compensation. The client interpolates between snapshots and predicts the player's own moves. The delay between a key press and its display drops to zero, even with 100 ms of latency (figure below).
  • Deployment. The server is a static binary in a scratch Docker image, running as nobody.
