NAME

octopus — deploy a five-service application on virtual machines

SYNOPSIS

ansible-playbook -i production playbook.yml --ask-vault-pass

DESCRIPTION

One command installs and starts the whole voting application on five virtual machines; running it again changes nothing. A second-year project. The same application is deployed on Kubernetes in bernstein(8).

voters ──► poll ──► redis ──► worker ──► postgresql ◄── result ◄── viewers
          (VM 1)   (VM 2)    (VM 3)       (VM 4)        (VM 5)

DESIGN

  • One role per service. base, redis, postgresql, poll, worker, result. Each role installs its runtime (Python virtualenv, Maven, Node.js) and a systemd service.
  • Idempotence. Each task describes a desired state; handlers restart a service only when its configuration changed.
  • Secrets. The database password is encrypted with Ansible Vault; the SSH key, the vault password file and the real inventory stay out of the repository.
  • PostgreSQL 16 from the official repository, schema applied and access restricted in pg_hba.conf.
